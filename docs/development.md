# 개발 작업 규칙

## 기본

- 날짜는 항상 KST: `TZ=Asia/Seoul date +%F`
- 작업은 `claude/` 접두사 브랜치에서 하고 PR로 올린다. main에 직접 푸시하지 않는다.
- 비밀값은 저장소에 두지 않는다.

## 외부 모델 검토 요청

이 저장소의 계획·코드·디자인은 다른 모델(Gemini, GPT 등)이 검토할 수 있다.

- 다음 경우에는 작업을 멈추지 말고 `docs/reviews/`에 검토 요청서를 만든다. 양식은 `docs/reviews/README.md`.
  - 되돌리기 어려운 구조 결정 (데이터 형식, 브랜치·PR 흐름)
  - 보안이 걸린 부분 (워크플로 권한, 토큰, 외부 입력 처리)
  - 사용자에게 보이는 디자인 시안
  - 예약 실행 지침(`docs/runbook.md`)의 큰 변경
- 요청서에는 구체적인 질문과 "이미 고려한 것"을 반드시 쓴다.
- PR 설명에 요청서 링크를 남기고, 사용자에게 검토 요청이 있음을 알린다.
- 검토 결과가 붙으면 `대응` 표에 반영·보류·반대와 이유를 적는다. 지적을 그대로 따르지 않아도 되지만 이유는 남긴다.
